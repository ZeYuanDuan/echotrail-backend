# Persisted Events and Dashboard API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Persist confirmed Echo Cards per named user, serve My Trail in creation order, and save a full Dashboard snapshot only after an explicit rebuild request.

**Architecture:** Fastify routes call a small PostgreSQL repository. Event confirmation writes conversation, messages, event, insight, and grounded signals in one transaction. Dashboard rebuild loads all confirmed insights, asks Gemini for a whole-history narrative, calculates chart aggregates from saved signals, then publishes one JSON snapshot if the user's insight revision is unchanged.

**Tech Stack:** Node 22, TypeScript, Fastify 5, `pg`, PostgreSQL, Gemini API, Vitest.

**Spec:** `../../../../echotrail-project-management/EchoTrail-MVP-SPEC.md` (repository sibling; persistence contract, A-5, B-1, C-10). **Prerequisite:** [Cloud Build database migrations](2026-09-25-cloud-build-migrations.md). **Consumer:** frontend plan at `../../../../echotrail-frontend/docs/superpowers/plans/2026-09-25-persisted-echo-flow.md`.

## Global Constraints

- A nickname maps to one stable `users.id`; this is a one-off demo with no authentication requirement.
- An unconfirmed Echo Card is a preview and creates no `events` or `event_insights` row.
- Confirming a card atomically writes one event plus one insight; My Trail reads it immediately, before any Dashboard update.
- `events.created_at` is generated by PostgreSQL. Sorting uses `created_at ASC, id ASC`; no occurred-at field or inference from story text.
- Rebuild reads **all** confirmed user insights. Dashboard GET reads the latest saved successful `dashboard_runs` row and never calls Gemini.
- Rebuild failure or a concurrent new card leaves the prior successful snapshot intact.
- Framework scores are a demo preview while C-7/C-8/C-9 aggregation remains open in the spec; label them as such, retain evidence, and keep the aggregation function isolated.

## Review Focus

1. Same `clientEventId` is retried after a lost response: return the original event without duplicate messages, insights, signals, or revision increment.
2. Two users use the same browser/device: every event and Dashboard query returns only rows for the supplied user ID.
3. Two events share the same database timestamp: My Trail order is stable via `id` tie break.
4. A new card is confirmed while Gemini rebuild is running: reject the stale result with 409, preserve the prior snapshot, and let the user retry.
5. Gemini gives malformed or ungrounded Dashboard evidence: reject the rebuild and preserve the prior snapshot.

## API contract and file map

| File | Responsibility |
| --- | --- |
| `src/persistence/types.ts` | Request and response types shared among routes, services, tests. |
| `src/persistence/validate.ts` | Nickname, UUID, card, signal, and quote validation. |
| `src/persistence/repository.ts` | SQL transactions and user-scoped reads/writes. |
| `src/persistence/dashboard.ts` | Whole-history synthesis input and deterministic signal aggregation. |
| `src/persistence/routes.ts` | HTTP status mapping and route registration. |
| `src/llm.ts` | Gemini method for whole-history Dashboard synthesis and output validation. |
| `src/app.ts`, `src/server.ts` | Register routes and inject/close DB pool. |
| `test/persistence-routes.test.ts`, `test/dashboard-rebuild.test.ts` | Real test-database API and stale-result cases. |

Use JSON camelCase externally and snake_case in SQL. All IDs are UUID strings. Routes:

```ts
POST /api/users                  { name: string } -> 200 { id: string, name: string }
POST /api/events                 { userId: string, clientEventId: string, conversationId?: string,
                                   messages: { role: 'user' | 'model', text: string }[],
                                   card: { title: string, happen: string[], emotion: string,
                                           like: string, dislike: string, value: string, quote: string },
                                   editedFields: Array<'title'|'happen'|'emotion'|'like'|'dislike'|'value'|'quote'>,
                                   signals: InsightSignal[] }
                                  -> 201 or idempotent 200 EventRecord
GET /api/events?userId=<uuid>    -> 200 { events: EventRecord[] }
POST /api/dashboard/rebuild      { userId: string } -> 200 DashboardSnapshot
GET /api/dashboard?userId=<uuid> -> 200 { dashboard: DashboardSnapshot | null }
```

`EventRecord = { id, userId, conversationId, createdAt, source, card, signals }`. `DashboardSnapshot = { id, userId, createdAt, sourceRevision, sourceEventCount, profile, frameworks }`; `profile` is the existing `InsightResult['dashboard']` shape; `frameworks` has `scores: Record<'riasec'|'disc'|'schein', Record<string,number>>` and `evidence: Array<{eventId,eventTitle,framework,dimension,strength,evidenceQuote}>`. Empty Dashboard is `null`. `POST /api/dashboard/rebuild` with zero events returns 409. Missing user returns 404. Invalid input returns 400; stale revision returns 409; Gemini failure returns current LLM error code. The frontend must show these as recoverable errors without redirecting.

```sql
WHERE e.user_id=$1 ORDER BY e.created_at ASC,e.id ASC;
```
